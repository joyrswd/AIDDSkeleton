# Definition Governance Routes

`definition/` owns project-specific adopted definition, lifecycle/status, procedures, identifiers, commands, constraints, and verification-basis rules.

Evaluate every route independently against the current action. Read every match before that action. Re-evaluate when work moves to a materially different phase or new facts change authority, responsibility, state, evidence, structure, or destination.

| Route | Read when | Destination |
|---|---|---|
| Structure / Navigation / Procedures | Work initializes or changes definition structure; creates/moves/renames/deletes/reclassifies definition docs; determines definition ownership/placement; adds or relocates content whose responsible document may differ from the one being edited; adds or changes reproducible prerequisites or instructions/steps for setup, execution, analysis, testing, documentation checks, deployment, migration, rollback, or operation; changes indexes/navigation/cross-responsibility routing; or creates/changes/classifies project procedures. | `structure.md` |
| Documentation Content / Language / Splitting | Work creates, adopts, or changes project-documentation content in `definition/`; determines or changes the documentation-language default/app override; or initializes documentation-language state. | `documentation-language.md` |
| Initialization / Reset | Repository-modifying project work is about to begin and initialization consistency has not yet been established for the current initialization artifacts; initialization artifacts/state are being inspected, reconciled, or changed; initialization is being performed; or an explicit reset to uninitialized is being considered/performed. | `initialization-reset.md` |
| Implementation Entry | Work is about to create/formalize a new implementation responsibility, start implementation for newly adopted/changed responsibility, or start/resume formal implementation after a change to applicable requirements/AC, RBs, adopted approach/design constraints, verification method, Blocker state, or implementation/lifecycle state. A change known to affect only non-normative wording/navigation/summary and none of those implementation prerequisites does not match solely because it occurred. A local edit to an already-entered formal implementation/test does not match solely because it is formal. | `entry-completion.md` |
| Completion | Work is about to judge implementation/project completion or advance completion/lifecycle state against project-definition conditions. | `entry-completion.md` |
| Normative Authority | Work may adopt, change, retire, abstract, relocate, or reclassify requirements/design/testing content; or may change an observable outcome, contract, invariant, compatibility obligation, data constraint, algorithm, RB, or other future implementation constraint. Decide this against the responsible SoTs resolved through State / Routing, not against assumed adopted content. | `normative-authority.md` |
| Realization Authority | Information learned from implementation, tests, configuration, generated output, or execution may be recorded in `definition/` or used to decide whether realization detail is normative. | `realization-authority.md` |
| Reconciliation / Transfer | Work moves/transfers/reclassifies definition material; reconciles definition material, responsibility, authority, ownership, classification, or retention during a migration/refactor/rename/rollout; changes definition authority/ownership/classification/retention; or retires a definition artifact/classification. | `reconciliation-transfer.md` |
| State / Routing | Work will read, rely on, or navigate to project-definition content for authority, expected behavior, or current state, **including when the responsible document already appears known**; must resolve responsible definition entries, cross-responsibility authority, or current lifecycle/implementation/verification state; or may change a responsibility index's current-state summary/routing. | `state-routing.md` |
| Verification Basis | Work is about to rely on, create, combine, retain, discard, reuse, downgrade, or report verification evidence/claims; or evidence is unavailable, stale, superseded, expirable, or conditionally reusable. | `verification-basis.md` |
| Maintenance / Validation | Definition docs, indexes, governance routes, hierarchy, IDs, links, or derived/summary normative facts are being changed; validate documentation/governance consistency for that change. | `maintenance-validation.md` |

If a destination reveals another route condition, re-evaluate this index before continuing. If another responsibility area becomes involved, apply root cross-area routing.
