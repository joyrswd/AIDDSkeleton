# Reference Authority, Use, and Validation

## Authority Boundary

- Reference presence/linkage ≠ requirement/design/testing/implementation constraint/verification conclusion beyond recorded scope.
- A reference remains supporting input, not an adoption record.

## Use

- Preserve supplied originals in `references/`.
- Implementation, acceptance, or current verified-claim use requires Reference Validation.
- Adoption/formalization requires the destination area's authority process; a reference itself grants none.

## Reference Validation

- Verify relevant claim-bearing content, provenance, available integrity/version information, freshness, applicability conditions, links, usage references, and absence of prohibited sensitive content.
- When a reference is used as VB, evaluate `definition/.routes/index.md` and verify its sufficiency for the asserted scope.
