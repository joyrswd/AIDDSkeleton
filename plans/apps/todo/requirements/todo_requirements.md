# Todo 機能・品質要件

## 機能要件

- **TODO-REQ-01**: 利用者は 1～200 文字の Todo を登録できる。空白だけの入力は拒否する。
- **TODO-REQ-02**: 利用者は登録済み Todo の一覧と完了状態を確認できる。
- **TODO-REQ-03**: 利用者は Todo 本文と完了状態を更新できる。
- **TODO-REQ-04**: 利用者は Todo を削除できる。
- **TODO-REQ-05**: 登録・更新・削除の結果は SQLite に保存され、再読み込み後も維持される。
- **TODO-REQ-06**: 処理中、入力不備、API 失敗、空の一覧を画面上で識別できる。

## 品質と適用判定

- セキュリティは適用する。SQL はプリペアドステートメント、画面はテキスト DOM API を使う。
- プライバシーは限定適用する。個人情報の収集を目的とせず、データを外部送信しない。
- アクセシビリティは適用する。ラベル、キーボード操作、状態通知を提供する。
- 性能はローカルで 1,000 件程度を扱う範囲のシンプルな一覧取得を前提とし、専用目標は設けない。
- 可用性、監視、データ保持期間、リカバリ、本番運用はローカル検証用のため対象外。
- ライセンスはリポジトリルートの `LICENSE` に従う。追加依存は使用しない。

## 受入条件

- **TODO-AC-01**: 画面で作成した Todo が即座に表示され、ページ再読み込み後も表示される。
- **TODO-AC-02**: 完了切り替え、本文編集、削除が画面と API の両方で反映される。
- **TODO-AC-03**: 不正入力は 422 と説明可能な JSON エラーになり、画面が利用者に通知する。
